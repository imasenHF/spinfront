# 每日输出分类规则（词表1.2.0）

正式标签使用taxonomy/taxonomy.json中的标准ID。direction_ids仅允许nmr、epr，不能为空；同时涉及两者时写["nmr", "epr"]。不再生成nmr_epr、mrs或mrv方向ID。

活体磁共振波谱使用nmr方向与in_vivo_mrs实验类型；磁共振测速使用nmr方向与mr_velocimetry实验类型。单独的医学MRI及磁共振静脉成像不据此标注为测速。

每期taxonomy_version为1.2.0。sample_systems保留无法可靠映射的样品概念。UI方法组不生成正式ID，原有父子方法标签规则继续使用。

摘要、具体意义、发布时间和来源依照既有日报规则生成。tag_review_status与来源及日期复核状态分别记录；词表迁移不改变来源核验结论。屏幕正文、HTML和JSON保持一致，所有内容记录均无图片字段。

## 采购与需求动态固定末条（2026-10-17修订）

每天固定以“采购与需求动态”结束正文，先完成采购专项检索并预留末条，再选择其他资讯。范围包括直接涉及NMR/EPR整机、探头、谐振器、控制与数据系统及相关服务的采购意向、需求调查/征集、市场调研、招标/询价/磋商、变更/延期、成交/中标、终止/废标及合同公告；排除医学MRI泛采购。采购意向与需求调查按其实际阶段表述，不写成已启动招标，不虚构投标截止时间。

当期全部合格且未重复的公告统一合并为最后一条，通常安排最多9条其他资讯加1条采购汇总。摘要使用一个连续段落，以完整句和分号衔接，不设置项目子编号、项目符号或分点；只有一份合格公告也放在最后。已发布日报因补查追加时保留既有item_id与正文，新增采购汇总可作为第11条等末条，并在Review记为明确修订。

完成24小时优先检索和近7天回扫后仍无新增合格公告，末尾必须显示“采购与需求动态”核查说明，明确写“本期未检索到新增已核实公告”、核查范围、访问限制及已登记候选数。使用顶层procurement_status对象，字段为status（固定no_verified_updates）、title_cn（固定采购与需求动态）、summary_cn、checked_at（带时区的ISO时间）、registered_candidates（非负整数）。此说明不放入items，不标为tender，不计为采购公告或新增资讯；网页、下载版和屏幕版均显示在最后。存在tender汇总时不同时生成procurement_status。不得将旧公告重写成新增采购，不用无关项目填位。

每份公告仍独立核验相关性、公告实际发布日期、时间窗口、原始来源与历史重复。逐项目保留采购单位、仪器名称或配置、预算或最高限价、投标截止时间（适用时）、预计采购月份（意向公告适用）和实际采购阶段；仅写原始公告已确认的信息，缺失字段不补写。每个项目的公告日期写入摘要，独立来源链接以“采购单位＋项目简称”标识，与段落中的项目逐一对应。长摘要按实际公告数调整，不受普通条目的100–150字限制；具体意义只写公告中的配置、时间或采购条件，保持连续段落。厂商设备部署新闻不因涉及安装而自动归为采购公告。

沿用现有JSON结构，采购汇总只占一个items记录，information_type使用tender；direction_ids依各公告实际对象使用nmr、epr或两者。首个项目的原始公告写入source/url，其余独立公告写入alternative_sources；此处各链接对应不同项目，不宣称为同一事件的替代来源。主publication_date取所含公告中最晚的实际发布日期，各项目原始日期同时保留在正文和Review日志。只有所有公告均已确认位于近24小时窗口时，汇总time_scope才使用24h；含近7天扩展公告时统一使用7d_extension，并在正文交代各日期。合并条目doi留空。

范围说明和Review日志分别记录“日报条目数”与“采购公告数”，例如10条日报内容中采购汇总包含3份公告。Review候选继续逐公告记录标题、采购单位、公告日期、原始URL、查重结果及入选或排除理由；被排除的采购候选也逐条保留。日志明确记录已登记采购候选数、合格公告数、排除数及汇总item_id；未完整保存全部搜索命中时，只报告已登记候选数，不把它写成搜索命中总数。历史查重须同时检查采购汇总的url、alternative_sources中的各项目URL及Review逐公告记录，避免同一公告在后续汇总中再次出现。屏幕版、网页与下载版保持同一条目、同一段落和同一组来源链接。

采购原文访问补查：动态列表为空或普通页面读取失败时，继续检查官方列表、原始链接及页面实际调用的公开只读接口；不得把未渲染内容视为无公告。东方招标公开列表由js/config.min.js中的baseURL与TenderProjectPagedList生成，按项目编号或名称检索后，以FormNo读取TenderProjectByFormNo；TenderContent是公告正文，ReleaseTime是发布字段，CreateDate不能单独代替发布日期。详情页格式为https://www.oitccas.com/pages/tender_online_info.html?FormNo=<实际返回值>。仅访问无需登录的公开记录，不处理购买、报名或投标操作。搜索引擎缓存列表与实时官网不一致时重新读取官方页面，并记录返回状态。
